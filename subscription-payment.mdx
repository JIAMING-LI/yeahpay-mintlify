订阅支付适合会员续费、软件服务和内容订阅等需要多次收款的业务。消费者通过统一收银台完成首次支付并授权；授权生效后，商户按双方约定发起后续支付，消费者无需再次进入收银台。

<Note>
  YeahPay 提供客户、订阅授权和后续支付能力。订阅周期、套餐、计费日期、重试策略以及服务履约由商户系统管理。
</Note>

## 完整接入流程

<Steps>
  <Step title="创建客户">
    调用 [`POST /consent-payment/customers/create`](/api-reference/订阅支付/创建客户)，使用商户侧唯一且不变的 `merchantCustomerId` 创建客户，并保存响应中的 `customerId`。
  </Step>
  <Step title="创建首次支付收银台">
    调用[获取统一收银台地址](/api-reference/统一收银台/获取统一收银台地址)接口，传入 `checkoutMode=CONSENT_INITIAL`、`consumerInfo.customerId` 和 `paymentConsent`，参数要求见下表。
  </Step>
  <Step title="完成首次支付并取得 consentId">
    消费者完成首次支付后，YeahPay 创建订阅授权，并在支付结果通知中返回 `consentId`。商户验签并确认支付成功后，应保存 `consentId`，用于订阅管理和后续支付。
  </Step>
  <Step title="管理订阅">
    使用 `consentId` 查询订阅状态；消费者停止订阅时取消授权，需要恢复时重新启用授权。
  </Step>
  <Step title="发起后续支付">
    商户根据自己的计费计划调用[创建支付意图](/api-reference/支付意图/创建支付意图)接口，在 `payment_consent` 中传入 `paymentInitiator=MIT` 和 `consentToken`（值为首次支付取得的 `consentId`），并通过支付结果通知或查询支付意图确认最终结果。
  </Step>
</Steps>

## 首次支付参数

调用统一收银台接口时传入以下参数：

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `checkoutMode` | `CONSENT_INITIAL` | 表示本次支付用于创建订阅授权 |
| `consumerInfo.customerId` | 创建客户接口返回值 | 标识完成首次支付与授权的客户 |
| `paymentConsent.paymentInitiator` | `MERCHANT` | 支付发起方，目前仅支持商户发起 |
| `paymentConsent.paymentType` | `scheduled` 或 `unscheduled` | 支付类型：计划扣款或非计划扣款 |

<Warning>
  必须先创建客户，再创建首次支付收银台。只有首次支付成功且返回 `consentId` 后，订阅授权才可用于后续支付；创建收银台成功不代表支付或授权成功。
</Warning>

## 客户管理

客户用于识别完成首次支付并授予后续支付权限的消费者。

- `merchantCustomerId` 由商户生成，在同一商户下必须唯一且保持不变。
- 创建客户后保存 YeahPay 返回的 `customerId`，创建首次支付收银台时必须传入。
- 客户姓名、邮箱、手机号或地址发生变化时，可以更新客户资料。
- 可以使用 `customerId` 或 `merchantCustomerId` 查询客户；一个客户可以关联多个订阅授权。

## 支付结果通知与 consentId

创建首次支付收银台时传入 `notificationUrl`。首次支付成功并创建订阅授权后，支付结果通知会在普通支付字段之外返回 `consentId`。

```json
{
  "status": "2",
  "merchantId": "0004905629",
  "thirdOrderId": "SUBSCRIPTION_INITIAL_001",
  "leshuaOrderId": "YEAHPAY_ORDER_ID",
  "consentId": "con_yk_2ee6fa94d3b8046c8cb4dc817dd28a3f"
}
```

收到通知后：

1. 使用完整回调地址和原始请求体验证通知签名。
2. 检查支付状态并按商户订单号幂等处理。
3. 保存 `consentId` 与商户客户、首次支付订单及订阅业务的关联关系。
4. 成功接收后返回纯文本 `success`；若未及时收到通知，可通过订阅查询接口补偿获取 `consentId`。

## 订阅管理

订阅由 `consentId` 唯一标识。商户应保存订阅与自身会员、套餐或服务关系，不要使用渠道侧标识作为业务主键。

| 状态 | 含义 | 可执行操作 |
| --- | --- | --- |
| `active` | 订阅授权有效 | 查询、取消、发起后续支付 |
| `cancelled` | 商户或消费者已停止订阅 | 查询、重新启用 |
| `suspended` | 平台暂停该订阅 | 仅查询；恢复后才能继续操作 |

## 后续支付

只有 `active` 状态的订阅可以发起后续支付。每次后续支付都是一笔独立交易，商户需要自行决定扣款时间与金额。

后续支付调用 [`POST /openapi/v2/createIntent`](/api-reference/支付意图/创建支付意图)。请求的 `payment_consent` 中携带有效的 `consentToken` 时，YeahPay 在建单时直接发起扣款，消费者无需进入收银台。

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `customerId` | 创建客户接口返回值 | 与首次支付时的客户一致 |
| `payment_consent.paymentInitiator` | `MIT` | 商户发起的后续扣款 |
| `payment_consent.consentToken` | 首次支付取得的 `consentId` | 订阅授权标识 |
| `requestId` | 商户生成 | 建单幂等标识，网络重试时复用原值 |
| `merchantOrderId` | 商户生成 | 每笔后续支付唯一，用于对账 |
| `amount` | 大于 0 的整数 | 最小货币单位，例如 SGD 10.00 传 `1000` |
| `currency` | 三位字母币种码 | 须为商户已开通的币种 |
| `callback.notificationUrl` | 可选 | 本次支付结果通知地址，须为 HTTPS；不传时使用应用默认通知地址 |

```json
{
  "merchantId": "SAMPLE_MERCHANT_ID",
  "requestId": "renewal-202611-001",
  "merchantOrderId": "SUBSCRIPTION_RENEWAL_202611_001",
  "amount": 1000,
  "currency": "SGD",
  "customerId": "cus_yk_example",
  "payment_consent": {
    "paymentInitiator": "MIT",
    "consentToken": "con_yk_2ee6fa94d3b8046c8cb4dc817dd28a3f"
  },
  "callback": {
    "notificationUrl": "https://shop.example.com/payment/notify"
  }
}
```

<Warning>
  `consentToken` 只能在商户服务端保存和使用，不得下发浏览器。MIT 后续扣款不要传 `deviceId`。
</Warning>

确认扣款结果：

- 响应 `code=0` 只表示请求被正常处理，需读取 `data.status`：`SUCCEEDED` 表示扣款成功；`PENDING` 时使用原 `paymentIntentId` 或 `merchantOrderId` [查询支付意图](/api-reference/支付意图/查询支付意图)，不要重复扣款。
- 返回 `292009`、`500` 或请求超时时，扣款可能已经发起，应先查询原订单；重试时沿用原 `requestId` 和 `merchantOrderId`。
- 支付成功通知的格式与处理要求见[嵌入式收银台](/embedded-checkout)。

需要查看历史记录时，调用[查询扣款列表](/api-reference/订阅支付/查询扣款列表)，按 `consentId` 分页查询订单号、金额、币种、状态和支付时间。
